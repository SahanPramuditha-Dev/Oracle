Privacy policy

Prepared for publication on 5 November 2026. Operator and contact: Sahan Pramuditha, sahan.dev.tech@gmail.com.

This policy covers Oracle's local personal-assistant application, its optional Google connection, and this informational website. The current application is a single-user development project running on the operator's Windows computer. It is not a hosted multi-user service.

1. Google information accessed

  • Identity: Google's stable account identifier and verified email address, used to identify the connection and display the signed-in account.
  • Calendars: calendar identifiers, names, access roles and timezones; upcoming event identifiers, titles, start/end times, status and links.
  • Tasks: task-list identifiers and titles, and task identifiers, titles, due dates and completion status.
  • Authorization: Google access and refresh tokens, granted scopes and expiry information, used to maintain the access you approve.

Oracle requests identity, Calendar-event, read-only calendar-list, and Tasks permissions. It does not request Gmail or Google Drive access in this connector.

2. How Google information is used

The connection lets you choose a calendar or task list, view upcoming events and tasks, create Calendar events with notification settings, create tasks, and complete or reopen tasks. Loading and writing Google records are user actions. Oracle does not run a background two-way Google synchronization service.

A local reminder may prefill an event form. Publishing that form creates a separate record in Google Calendar; later local changes do not update the Google copy automatically. Oracle does not add attendees or send event-update emails through this workflow.

3. Sharing, AI and Limited Use

Google API information is transferred between Google's services, the local Oracle backend and the application's browser interface to provide the features described above. Google data accessed by this connector is not supplied to Oracle's AI providers, used to train AI models, sold, or used for advertising. Human access is limited to the person operating the local application and any access they choose to grant to their own computer.

When Oracle accesses Google API data, it follows the Google API Services User Data Policy and its Limited Use requirements. New uses of Google data would require an updated policy and appropriate user consent.

4. Storage and protection

Google account identity and OAuth tokens are saved in a backend-only credential file encrypted with Windows DPAPI for the current Windows user. The OAuth client configuration is a separate private local file excluded from the project's repository. Access and refresh tokens are not returned to frontend JavaScript.

Fetched Google event/task content is displayed in browser memory; this connector does not copy that content into the local notes database or a search index automatically. Records you explicitly create in Google remain in your Google account. Local reminder records remain in the application's own database.

Operational logs may contain request paths, resource identifiers and response status codes. OAuth callback query values are filtered from the local server's access log. Access depends on the security of the local computer and account; encryption does not protect an unlocked computer from its authorized operator.

5. Retention, deletion and revocation

Stored account identity and tokens remain until you disconnect or remove the local credential file. Choose Workspace → Google → Disconnect Google to remove Oracle's stored connection and attempt token revocation. If revocation fails, Oracle reports this; you can also remove access in your Google Account connections.

Disconnecting does not delete events or tasks from Google, local reminders, user-managed backups or operational logs. You control Google records through Google Calendar and Tasks. Local data can be removed through Oracle's relevant controls. Copies or logs you maintain on your own computer require your own retention and deletion choices.

For access, correction or deletion questions, contact the operator at the email above. Do not include passwords, OAuth tokens or client secrets in an email.

6. Other assistant features

Typed conversation and recent context may be processed by the selected local or cloud model, depending on the application's configuration. Camera, image, microphone and speech features have separate permission and processing flows. These features do not obtain Google Calendar or Tasks data from this connector. Review the application's processing indicators and configuration before providing personal information.

Local notes, reminder due times, explicitly saved image memories and their descriptions are stored in the application's database. If the operator enrolls a person for face matching, the local database stores that person's name, notes and biometric face-template samples. The operator must have that person's authorization before enrollment. Person and sample deletion controls remove the active stored records; user-managed backups require separate handling. These features are separate from Google Calendar and Tasks access.

7. Website and hosting

This informational site has no account form, analytics scripts, advertising or application-data upload feature. The hosting provider may process ordinary technical request information, such as IP addresses, for delivery, security and service operation. See Google's privacy policy for its services.

8. Changes and contact

The operator will update this policy when the application's data practices change. The publication date appears above. Questions can be sent to sahan.dev.tech@gmail.com.
